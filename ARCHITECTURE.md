# Литературный архитектор — архитектура 0.1

Локальное приложение: браузер → HTTP на 127.0.0.1 → Python → SQLite.
Зависимости: только Python 3.11+, стандартная библиотека. Никаких CDN.

Слои: core.py (импорт, сегментация, измерения, адаптер LLM), app.py
(хранение и HTTP), index.html (русский интерфейс). SQLite содержит книги,
абзацы с устойчивыми ID, карточки, замечания, канон и историю. Перед
принятием правки создаётся SQLite backup. Предложения никогда не меняют
рукопись автоматически. Каждая правка проверяет совпадение исходного текста.

Большие книги анализируются порциями до 12000 символов с перекрытием
между порциями, кратким структурным паспортом, каноном и накопленным
резюме предыдущих порций. Резюме — сжатое представление, не гарантия
полного контекста. Локальный аудит не претендует на литературную экспертизу.
LLM получает текст как данные, возвращает JSON с ID и точной цитатой;
неподтверждённые ссылки отбрасываются. Результат требует проверки автором.
Ключ API используется только в текущем запросе, не сохраняется на диск.

Режимы: аудитор ищет проблемы; шеф-редактор предлагает точечную редакцию;
хранитель канона проверяет согласованность; соавтор предлагает добавления.
В MVP API совместим с OpenAI Chat Completions (включая локальные серверы).
Другие протоколы требуют адаптеров. Запросы запускаются вручную и отправляют
рукопись выбранному пользователем провайдеру.

Этапы: 1) импорт/структура/карточки/аудит; 2) подтверждение правок,
DOCX, история/backup, постоянный канон; 3) дальнейшее развитие извлечения
событий, семантического поиска по серии, графа отношений и хронологии.
Первая версия включает этап 1 и базовые механизмы этапа 2; полноценная
проверка истории и автоматическое построение отношений пока не реализованы.
